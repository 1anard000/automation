The Business — What Dify Is

One sentence: Dify is an open-source platform that lets teams build, deploy, and operate AI agent workflows visually — without writing code from scratch.

What it does: Sits between AI models (GPT, Claude, Llama, Qwen, DeepSeek) and business systems (CRM, databases, support tools). Visual drag-and-drop builder for AI workflows, RAG pipelines (connecting AI to company data), agent creation, and production deployment.

Who uses it: Maersk, Adobe, Google, PayPal, Novartis, Deloitte, Mercedes-Benz, McDonald's, Volvo, ETS, Anker — 280+ enterprise customers.

Founded: March 2023 by Luyu Zhang. Entity: LangGenius, Inc., Menlo Park, CA. Offices: SF Bay Area, Tokyo, Shanghai, Suzhou. ~50-100 employees. "Over 60% of codebase built by LLMs."

Important: Dify is under the langgenius GitHub org. LangGenius is Dify's company name — NOT related to LangChain (langchain-ai). They are separate companies and competitors.

Opening — "Tell me about yourself and why Dify?"

This is your narrative arc. Lead with this. ~2 minutes.

"Three roles converge at Dify.

Amazon I was on the Global Selling team — helping APAC sellers across Southeast Asia, Korea, and Taiwan reach Western consumers. That's GTM for Asian companies going international. The #1 lesson: going international isn't about translating your product — it's about rebuilding trust. Compliance, reference customers, local presence. Dify faces the exact same challenge.

GitHub I was on the developer platform team. I watched the PLG playbook work in real time: developers adopt for free, bring to work, enterprise follows. I was there when Copilot launched — an AI product layer on an open-source platform. That's exactly what Dify is building.

Salesforce I learned how enterprises actually buy software. The procurement cycles, the security reviews, the compliance requirements. The partner ecosystem — Accenture, Deloitte, PwC — drove more enterprise adoption than direct sales.

Dify sits at the intersection: a platform going global Amazon, built on open-source GitHub, selling to enterprises Salesforce. That's why I reached out.

I was originally skeptical of AI platforms — the model layer has unsustainable economics. But Palantir's thesis convinced me. Karp said models are commoditizing — 'winners and losers swap places every six months' — and models alone produce 'strings of text' without enterprise grounding. What you need is an 'intermediate representation of the enterprise that AI can interact with.' That's what Dify is building."

Product Strategy — "What should Dify's product vision be?"

"Dify's vision should be: the operating system for AI-native work.

GitHub At GitHub, I watched the platform evolve from 'a place to host code' to 'the operating system for software development.' Each layer — Issues, PRs, Actions, Marketplace, Copilot — increased switching costs and ARPU. Dify should follow the same pattern. Today it's a workflow builder. Tomorrow it's the platform where every team's AI agents live. The Creator Center and Marketplace are the right moves — they're the GitHub Actions equivalent.

The three layers: Build (today — visual builder, RAG, agents), Collaborate (next 12mo — team workspaces, Human Input Node, audit trails), Ecosystem (18-36mo — Creator Center, Template Marketplace, third-party integrations). Layers 2 and 3 are happening simultaneously — v1.14.1 and the Marketplace shipped within a week. With $30M, Dify can parallelize."

Key Product Strategy Moves

3 moves (weave into answers):

  1. Absorb frameworks, don't compete. GitHub Git → GitHub. GitHub didn't compete with Git — it absorbed it. Most developers interact with GitHub, not Git directly. Dify should do the same with LangChain. Make LangChain invisible behind Dify's visual interface. But the window is closing — LangGraph Platform is building cloud-hosted agent deployment.
  2. Human Input Node = Trojan Horse for governance. Workflows pause for human review → audit trails → compliance without heavy RBAC. Bottom-up governance — same pattern as GitHub. Enterprises adopt the workflow first, then discover they need governance, then upgrade to Enterprise tier.
  3. Data grounding is the real moat. MongoDB + Voyage AI integration shows where Dify is going — native integrations to enterprise data sources. Every data connection creates switching costs. Model-agnosticism is table stakes; data-agnosticism is the next moat.

GTM Strategy — "How would you execute GTM?"

"Three motions, sequenced over 12 months:

Motion 1: PLG (months 1-3). GitHub At GitHub, the PLG playbook was: generous free tier → developers adopt → bring to work → IT discovers shadow usage → enterprise compliance gate → Enterprise contract. The developer IS the distribution channel. Dify has 1.4M installations — that's the funnel. The conversion is the challenge. I'd measure the free → paid rate, identify drop-off points, and run experiments. Target: 2-5% (GitHub benchmark).

Motion 2: Enterprise sales (months 3-9). Salesforce At Salesforce, I learned enterprise sales is about removing objections, not creating desire. The desire is already there — developers want AI tools. The objections are: security, compliance, governance, support. Dify's enterprise tier addresses all of them. The play: 'Your developers are already using Dify. Let's make it official with enterprise features.' Different buyers need different value props — the developer, the IT leader, the CFO all have veto power.

Motion 3: Partner channel (months 6-12). Salesforce At Salesforce, the partner ecosystem — Accenture, Deloitte, PwC — drove more enterprise adoption than direct sales. Partners are trusted advisors with existing relationships. If Dify is their recommended platform, that's instant pipeline. Partner margin: 30-40% discount. In APAC, system integrators are the fastest path. In the US, developer advocacy and PLG."

Competitive Landscape — "How do you think about competition?"

"GitHub At GitHub, I watched the competitive dynamics with GitLab, Bitbucket, Azure DevOps. GitHub won not by being a better Git client — it won by owning the ecosystem. Actions, Marketplace, Copilot — each layer created switching costs. Dify should do the same. Don't compete with LangChain — absorb it. Make frameworks invisible behind the visual interface. The platform that attracts the most creators wins.

The landscape has three layers:

Layer 1: Platform competitors — n8n (196K stars, biggest direct threat), Google Gemini EAP (enterprise benchmark), Microsoft Copilot Studio (distribution advantage). These are big companies with enterprise relationships.

Layer 2: Framework competitors — LangChain is moving up into Dify's territory. LangGraph Platform = cloud-hosted agent deployment. The window to absorb them is closing.

Layer 3: AI coding agents — Claude Code, Cursor, Copilot. These are different — they're tools for developers writing code, not platforms for deploying workflows. Claude Code helps you BUILD a Dify workflow. It can't REPLACE Dify.

Three competitors were just acquired (Flowise → Workday, Stack AI → Asana, Pipedream → Workday). Consolidation validates the space. Dify is one of the last independent open-source AI platforms with enterprise traction."

Unit Economics — "How do you think about monetization?"

"GitHub At GitHub, I saw the token economics up close — Copilot was losing money on every user because of model costs. That's why the orchestration layer is different. Dify passes model costs through to customers (bring-your-own API keys). Gross margins can be 70-80% — much higher than model-layer companies.

The open-source monetization pattern is proven: GitLab, Elastic, Confluent, Databricks all get 60-80% of revenue from cloud. Dify should follow the same path. The key question for the CFO: what's the cloud vs. self-hosted revenue mix? Where is Dify on that trajectory?"

Risk Factors — "What could go wrong?"

Top 3 risks:

  1. Community Edition cannibalization. Enterprises self-host for free. Mitigation: Make Cloud so good they choose managed. GitHub solved this exact problem.
  2. n8n overtaking Dify. More stars, higher scores. Mitigation: Double down on AI-native (RAG, agents) where n8n is weaker.
  3. Hyperscaler "good enough." Mitigation: Model-agnosticism + open-source trust. Enterprises don't want lock-in.
